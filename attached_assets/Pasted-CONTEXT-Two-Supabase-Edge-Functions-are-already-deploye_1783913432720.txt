CONTEXT

Two Supabase Edge Functions are already deployed and working (do not
recreate them, do not touch them):

  - create-razorpay-order — authenticated call, returns
    { order_id, amount, currency, key_id }. It creates the Razorpay order
    server-side and records a row in the `payments` table
    (status: "created"). It will return an error if the user's surprise
    is already is_paid = true.
  - verify-razorpay-payment — authenticated call, accepts
    { razorpay_order_id, razorpay_payment_id, razorpay_signature } in the
    JSON body, verifies the signature server-side using the Razorpay
    secret (never exposed to the client), and on success sets
    is_paid = true on the user's surprises row. Returns { success: true }
    or an error.

Both are called the standard Supabase way:
  const { data, error } = await supabase.functions.invoke("create-razorpay-order")
This automatically forwards the logged-in user's auth token, so no manual
header wiring is needed.

The Razorpay Key Secret is stored only as a Supabase Edge Function secret
— it must never appear in any frontend file. Only the Key ID (public,
already returned by create-razorpay-order as key_id) is safe to use in
the browser.
